# BUG-003 — Формируется некорректное значение checkout, при обновлении только checkin

**Severity:** Значительный  
**Priority:** Вымсокий  
**Status:** Открыт  
**Method:** `PATCH`  
**Endpoint:** `/booking/{id}`

## Краткое описание
При выполнении обновления только даты въезда формируется некорректное значение даты выезда. При этом обновление сразу двух дат выполняется корректно.

## Предусловия
- Restful Booker API доступен.
- Получен действующий токен авторизации

## Тестовые данные
JSON для POST:
```
{
  "firstname": "Алина",
  "lastname": "Рыбкина",
  "totalprice": 14570,
  "depositpaid": true,
  "bookingdates": {
    "checkin": "2026-09-25",
    "checkout": "2027-10-10"
  },
  "additionalneeds": "Завтрак на шведском столе"
}
```
JSON для PATCH:
```
{
    "bookingdates": {
        "checkin": "2025-09-15"
    }
}
```
## Шаги воспроизведения
1. Выполнить PUT `POST /booking` с телом запроса из тестовых данных. 
2. Выполнить GET `/booking/{bookingid}` и зафиксировать текущее значение `checkout`.
3. Отправить PATCH `/booking/{bookingid}` с телом запроса из тестовых данных.
4. Проверить response body.
5. Выполнить повторный GET `/booking/{bookingid}`.
6. Сравнить значения checkin и checkout с исходными данными.

## Ожидаемый результат
- Значение checkin изменяется на указанное при запросе PATCH.
- Значение checkout сохраняется без изменений.
- Остальные поля бронирования не изменяются.

## Фактический результат
API возвращает 200 OK, но значение checkout, не переданное в PATCH-запросе, изменяется на некорректное значение: `0NaN-aN-aN`. Последующий GET `/booking/{bookingid}` подтверждает сохранение некорректного значения checkout.
Response:
```
{
    "firstname": "Алина",
    "lastname": "Рыбкина",
    "totalprice": 14570,
    "depositpaid": true,
    "bookingdates": {
        "checkin": "2025-09-15",
        "checkout": "0NaN-aN-aN"
    },
    "additionalneeds": "Завтрак на шведском столе"
}
```
