# Частичное обновление бронирований — Test Cases

## Base URL: https://restful-booker.herokuapp.com

## Endpoint
`PATCH /booking`

## Тестовые сценарии
- Обновление одного поля в бронировании
- Обновление нескольких полей в бронировании
- Обновление одного вложенного объекта (даты въезда)
- Обновление несуществующего бронирования
- Обновление бронирования с пустым объектом
- Обновление бронирования без авторизации

## TC-PATCH-001 — Обновление поля имени в бронировании

**Priority:** High  
**Type:** Functional / Positive  
**Method:** `PATCH`  
**Endpoint:** `/booking/{id}`

### Предусловия
- Restful Booker API доступен.
- Предварительно создано бронирование.
- Получен действующий токен авторизации.

### Тестовые данные
Не требуются.

### Шаги
1. Отправить GET `/booking/{id}` по предварительно созданному бронированию и сохранить исходные данные.
2. Отправить PATCH `/booking/{id}`, в теле запроса содержится `firstname` с валидным значением.
3. Проверить HTTP status code.
4. Проверить данные response body.
5. Отправить GET `/booking/{id}` для того же `bookingid`.
6. Сравнить данные из GET с данными, переданными в PATCH.

### Ожидаемый результат
- API возвращает `200 OK`.
- Response PATCH содержит полную информацию о бронировании и обновленные данные `firstname`.
- GET `/booking/{id}` возвращает 200 OK.
- Данные бронирования, за исключением поля `firstname`, после повторного выполнения GET соответствуют первоначальным данным. Значение `firstname` соответствует значению, переданному в PATCH.

### Результат выполнения
**Status:** Passed

**Фактический результат:**
API вернул `200 OK`.
Response PATCH содержит переданные при обновлении данные, а также исходные данные бронирования. Последующий GET `/booking/{id}` вернул 200 OK и подтвердил сохранение изменений. Фактическое значение `firstname` соответствует данным, переданным в PATCH.

3. Проверить HTTP status code.
4. Проверить данные response body.
5. Отправить GET `/booking/{id}` для того же `bookingid`.

### Результат выполнения
**Status:** Failed

**Фактический результат:**

**Дефект:**
`BUG-003 — Формируется некорректное значение checkout, при обновлении только checkin`
