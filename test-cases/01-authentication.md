# Авторизация — Test Cases

## Base URL: https://restful-booker.herokuapp.com

## Тестовые сценарии
- Авторизация с валидными учётными данными
- Авторизация с неверным паролем
- Авторизация с неверным username
- Авторизация с пустым password
- Авторизация с пустым username
- Авторизация без обязательного поля

## TC-AUTH-001 — Авторизация с валидными учётными данными

**Priority:** High  
**Type:** Positive  
**Endpoint:** `POST /auth`

### Предусловия
- Restful Booker API доступен.

### Тестовые данные
Не требуются

### Шаги
1. Отправить `POST` запрос на `/auth` с корректными `username` и `password`.
2. Проверить HTTP status code.
3. Проверить структуру response body.

### Ожидаемый результат
1. API возвращает статус `200 ОК`.
2. Response содержит `token` с не пустым значением.

### Результат выполнения
**Статус:** Passed

**Фактический результат:**
API вернул 200 OK и вернул значение токена в `token`.


## TC-AUTH-002 — Авторизация с неверным паролем

**Priority:** High  
**Type:** Negative  
**Endpoint:** `POST /auth`

### Предусловия
- Restful Booker API доступен.

### Тестовые данные
Не требуются

### Шаги
1. Отправить `POST` запрос на `/auth` с корректным `username` и некорректным `password`.
2. Проверить HTTP status code.
3. Проверить структуру response body.

### Ожидаемый результат
1. Авторизация не выполняется, токен не выдаётся

### Результат выполнения
**Статус:** Passed

**Фактический результат:**
API вернул 200 OK, но токен не выдан. Response содержит `"reason": "Bad credentials"`. В документации не сказано об обязательности ошибочного статус-кода в ответе.
