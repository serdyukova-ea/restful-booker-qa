# Получение списка бронирований — Test Cases

## Base URL: https://restful-booker.herokuapp.com

## Endpoint
`GET /booking`

## Тестовые сценарии
- Получение списка бронирований и проверка структуры элементов списка
- Фильтрация по имени
- Фильтрация по фамилии
- Фильтрация по дате заезда
- Фильтрация по дате выезда
- Комбинация фильтров

## TC-LIST-001 — Получение списка бронирований

**Priority:** High  
**Type:** Functional / Positive  
**Method:** `GET`  
**Endpoint:** `/booking`

### Предусловия
- Restful Booker API доступен.
- В системе существуют бронирования.

### Тестовые данные
Не требуются.

### Шаги
1. Отправить `GET` запрос на `/booking`.
2. Проверить HTTP status code.
3. Проверить тип response body.
4. Проверить структуру элементов списка.
5. Проверить наличие поля `bookingid` в элементах списка.

### Ожидаемый результат
- API возвращает `200 OK`.
- Response body содержит список бронирований.
- Каждый объект содержит поле `bookingid`.
- `bookingid` содержит идентификатор бронирования.

### Результат выполнения
**Status:** Passed

**Фактический результат:**
API вернул `200 OK`.
Response содержит массив бронирований. Каждый элемент массива представлен объектом с полем `bookingid`.

### `TC-LIST-006 — Фильтрация бронирований по имени и фамилии`

**Priority:** High  
**Type:** Functional / Positive  
**Method:** `GET`  
**Endpoint:** `/booking?firstname={firstname}&lastname={lastname}`

### Предусловия
- Restful Booker API доступен.
- Предварительно создано бронирование с заполненными именем и фамилией.

### Тестовые данные
Значение из `firstname` и `lastname` предварительно созданному бронированию вписать в параметры запроса.

### Шаги
1. Отправить `GET` запрос на `/booking?firstname={firstname}&lastname={lastname}`, где `firstname` и `lastname` соответствуют значениям из созданного ранее бронирования.
2. Проверить HTTP status code.
3. Проверить наличие поля `bookingid` в response body.

### Ожидаемый результат
- API возвращает `200 OK`.
- Response содержит только бронирования, соответствующие одновременно заданным значениям `firstname` и `lastname`.
- Значения `firstname` и `lastname` в возвращённых бронированиях соответствуют значениям, указанным в параметрах запроса.
- В теле ответа содержится поле `bookingid` с идентификатором бронирования.

### Результат выполнения
**Status:** Passed

**Фактический результат:**
API вернул `200 OK`.
В Response вернулся список бронирований, соответствующих одновременно заданным значениям `firstname` и `lastname`. Все возвращённые бронирования содержат указанные значения имени и фамилии.
В каждом объекте присутствует `bookingid`.
