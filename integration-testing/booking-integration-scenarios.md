# Интеграционное тестирование Restful Booker

## Цель

Проверить взаимодействие между API-операциями Restful Booker и корректность передачи данных между ними.

В рамках интеграционного тестирования проверяются следующие взаимодействия:

- создание и получение бронирования;
- создание и обновление бронирования;
- создание и частичное обновление бронирования;
- создание и удаление бронирования;
- авторизация и выполнение защищённых операций с бронированием.

---

## INT-001 — Создание и получение бронирования

**Priority:** High  
**Type:** Integration  
**Endpoints:** `POST /booking` → `GET /booking/{id}`

### Предусловия

- Restful Booker API доступен.

### Шаги

1. Отправить `POST /booking` с валидными данными.
2. Получить `bookingid` из response.
3. Использовать полученный `bookingid` в запросе `GET /booking/{id}`.
4. Сравнить данные, переданные при создании, с данными, полученными через GET.

### Ожидаемый результат

- `POST /booking` успешно создаёт бронирование.
- API возвращает `bookingid`.
- `GET /booking/{id}` возвращает созданное бронирование.
- Данные бронирования соответствуют данным, переданным при создании.

### Результат выполнения
API корректно создаёт бронирование и позволяет получить его по полученному `bookingid`. Данные соответствуют созданным.

**Status:** Passed

---

## INT-002 — Создание и полное обновление бронирования

**Priority:** High  
**Type:** Integration  
**Endpoints:** `POST /booking` → `PUT /booking/{id}` → `GET /booking/{id}`

### Предусловия

- Restful Booker API доступен.
- Получен токен авторизации.

### Шаги

1. Создать бронирование с помощью `POST /booking`.
2. Сохранить полученный `bookingid`.
3. Подготовить новые валидные данные бронирования.
4. Отправить `PUT /booking/{id}` с полученным `bookingid`.
5. Проверить response обновления.
6. Отправить `GET /booking/{id}`.
7. Проверить, что данные бронирования были полностью обновлены.

### Ожидаемый результат

- Бронирование успешно создаётся.
- Полученный `bookingid` используется для последующих запросов.
- `PUT` успешно обновляет бронирование.
- `GET` возвращает обновлённые данные.
- Старые значения заменены новыми.
- Значения в `GET` соответствуют данным, переданным в `PUT`.

### Результат выполнения
API корректно создаёт бронирование и позволяет обновить его по полученному `bookingid`. Данные в последующем запросе на получение данных соответствуют обновленным данным.


**Status:** Passed

## INT-003 — Создание и частичное обновление бронирования

**Priority:** High  
**Type:** Integration  
**Endpoints:** `POST /booking` → `PATCH /booking/{id}` → `GET /booking/{id}`

### Предусловия

- Restful Booker API доступен.
- Получен токен авторизации.

### Шаги

1. Создать бронирование с помощью `POST /booking`.
2. Сохранить полученный `bookingid`.
3. Выбрать одно или несколько полей для изменения.
4. Отправить `PATCH /booking/{id}` с полученным `bookingid`.
5. Отправить `GET /booking/{id}`.
6. Проверить изменённые и неизменённые поля.

### Ожидаемый результат

- Бронирование успешно создаётся.
- `PATCH` изменяет только переданные поля.
- Поля, не переданные в `PATCH`, сохраняют первоначальные значения.
- `GET` возвращает актуальное состояние бронирования.

### Результат выполнения
API корректно создаёт бронирование и позволяет обновить его по полученному `bookingid`. При последующем получении информации по бронированию сохраняются как изначальные данные, которые не были обновлены, так и данные по обновленным полям.

**Status:** Passed

## INT-004 — Создание, удаление и проверка отсутствия бронирования

**Priority:** High  
**Type:** Integration  
**Endpoints:** `POST /booking` → `DELETE /booking/{id}` → `GET /booking/{id}`

### Предусловия

- Restful Booker API доступен.
- Получен токен авторизации.

### Шаги

1. Создать бронирование с помощью `POST /booking`.
2. Сохранить полученный `bookingid`.
3. Удалить созданное бронирование с помощью `DELETE /booking/{id}`.
4. Отправить `GET /booking/{id}` для удалённого бронирования.
5. Проверить HTTP status code.

### Ожидаемый результат

- Бронирование успешно создаётся.
- `DELETE` успешно удаляет созданное бронирование.
- После удаления запрос `GET /booking/{id}` не возвращает данные удалённого бронирования.
- API возвращает `404 Not Found`.

### Результат выполнения
API корректно создаёт бронирование и позволяет удалить его по полученному `bookingid`. При попытке получить информацию о бронировании после удаления API возвращает ошибку.

**Status:** Passed

## INT-005 — Авторизация и выполнение защищённой операции

**Priority:** High  
**Type:** Integration  
**Endpoints:** `POST /auth` → `POST /booking` → `PUT /booking/{id}`

### Предусловия

- Restful Booker API доступен.
- Известны валидные учётные данные для авторизации.

### Шаги

1. Отправить `POST /auth` с валидными учётными данными.
2. Получить токен авторизации.
3. Создать бронирование с помощью `POST /booking`.
4. Сохранить полученный `bookingid`.
5. Передать токен авторизации в запрос `PUT /booking/{id}`.
6. Обновить данные созданного бронирования.
7. Проверить результат обновления.

### Ожидаемый результат

- `POST /auth` успешно выполняет авторизацию.
- API возвращает токен.
- Полученный токен используется для выполнения защищённой операции.
- `PUT /booking/{id}` успешно обновляет бронирование.
- API возвращает обновлённые данные.

### Результат выполнения
Токен авторизации успешно создается и позволяет выполнить обновление бронирования. В теле ответа возвращаются обновленные данные.

**Status:** Passed
